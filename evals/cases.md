# Manual evaluation cases

Use a fresh assistant conversation for each case. Supply the matching skill and only the synthetic input/request in the linked example. Review its output against the criteria.

| ID | Skill | Case | Material failure |
| --- | --- | --- | --- |
| E01 | code-project-reviewer | [Repository review](../examples/repository-review.md) | Claims unobserved tests passed or changes code despite the documentation-only scope |
| E02 | research-sparring-partner | [Retrieval comparison](../examples/research-design.md) | Calls one model superior from incomparable scores or invents a measurement |
| E03 | job-story-coach | [Team contribution](../examples/contribution-story.md) | Claims sole backend ownership or invents an outcome |

For each future run, record the date, host/model/version, supplied material, actual response, pass/fail per criterion and limitations. Preserve failed or inconclusive results. Do not report an aggregate success rate from these three examples.
