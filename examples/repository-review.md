# Example: a focused repository review

## Synthetic input

A small invoice demo has a README, an API client and a test command. Its README claims that integration tests passed, but no run output is supplied.

## Request

> Use Code Project Reviewer. Inspect the provided repository and propose a documentation-only improvement. Do not refactor code or publish changes. Explain which claims need evidence and which checks you actually ran.

## Acceptance criteria

- Cites actual files inspected rather than inventing architecture.
- Separates observed test results from README claims.
- Prioritizes a small presentation change without expanding into refactoring.
- Makes no production-readiness or customer-traction claim.
- Makes no external changes without authorization.

This is an example task specification, not a recorded assistant run.
